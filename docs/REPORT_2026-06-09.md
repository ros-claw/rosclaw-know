## 1. 摘要 (TL;DR)

**rosclaw-know 当前 shipped 状态**：`master`，14 个手工 curated 模式 + 385 个 Muse 蒸馏的合成簇 → 共 399 个 symptom_cluster 发布到 `bridge_index.json`，由姐妹仓 [`rosclaw-how`](https://github.com/ros-claw/rosclaw-how)（蹲在 `d07ddac`，`_CURATED_MIN_SIMILARITY = 0.60` preference floor）在请求时按相似度路由。

**对比实验（有 KH vs 没有 KH）**：

| 集合      |  n  | 有 KH | 没 KH |   Δ    |  t   | CI95 |
|-----------|----:|------:|------:|-------:|-----:|------|
| **ALL n=30**  | 540 | 9.746 | 9.481 | **+0.265** | +5.60 | [+0.17, +0.36] |
| ALL n=10      | 180 | 9.789 | 9.317 | +0.472 | +4.66 | [+0.27, +0.67] |
| **HOME n=30** | 300 | 9.627 | 9.207 | **+0.420** | +5.54 | [+0.27, +0.57] |
| HOME n=10     | 100 | 9.680 | 8.930 | +0.750 | +4.44 | [+0.42, +1.08] |
| **WILD n=30** | 240 | 9.896 | 9.825 | +0.071 | +1.55 | [-0.02, +0.16] |
| WILD n=10     |  80 | 9.925 | 9.800 | +0.125 | +1.79 | [-0.01, +0.26] |

非平手胜率 73.9% (102W / 36L / 402T over 540 paired obs)。

**几条要点**

1. **ALL 与 HOME-TURF 在 n=30 都强显著**（t > 5.5，CI 远离 0）。CI 宽度从 n=10 的 0.40 缩到 n=30 的 0.19，符合 1/√n 缩窄规律。
2. **效应量真实值 ≈ +0.27 (全局) / +0.42 (HOME)**，n=10 的 +0.47 / +0.75 在自然方差的上尾，约 40% 是 control 侧好运。但 n=10 的 CI 覆盖 n=30 的均值，所以两者不矛盾。
3. **WILD 卡在 LLM 知识天花板**：5 个野外冷点里 4 个（T_009, T_W_001, T_W_006, T_W_008）LLM 无注入也满分 9.7–10/10，无法再被 curated 抬高。T_W_002 是唯一仍有空间的冷点（无注入 9.20，注入 9.97）。
4. **结构化规则跑到自然终点**：iter1–iter4 是 5 个 sequential 的结构性改造（synth quality gate → 5 个 cold-coverage curated → empty-snippet fix → 0.60 preference floor）。iter5 想再走 vocab augment 路线（augment `anti_windup_pid` 的 standard_name）已经 paired 回归（−0.317，t=−2.60），已 revert。

## 4. 遇到的问题

### 4.1 方法学层面

#### P-1. n=10 的方差预算不够支撑 paired 比较

iter5 的 vocab augment 在 n=10 跑出 paired −0.317（t=−2.60），但这个数字几乎全部来自 16 个**没有改变路由**的任务的 control-side 噪声漂移。本应是 +0.6 的 targeted lift，结果 targeted 任务 T_W_007 已经在 10/10 saturate（LLM 知识天花板），实际贡献 +0.00。
→ **结论**：未来任何 curated 的 vocab augment 上线前必须 n=30 而非 n=10。

#### P-2. LLM 知识天花板（LLM-knowledge ceiling）

5 个野外冷点里 4 个 LLM 无注入也满分。这些任务上 curated 注入永远 lift = 0。事先不 probe baseline 就盲增 curated，会把 dev 时间烧在不可能 lift 的任务上。
→ **结论**：决定加 curated 前，先用 control-only 跑 baseline 看 C̄。如果 C̄ ≥ 9.7，放弃。

#### P-3. V4-flash judge 在 W_006 上呈双峰分布

step-3.7-flash 给 W_006 的 raw score 要么聚 2 分要么聚 8–9 分，n=10 mean Δ 可在两次独立运行间 ±3.50 漂移。已迁移到 deepseek-chat（更确定，但 control 也有 server-restart 漂移）。
→ **结论**：高方差任务上不要单跑 n=10，要看多次独立运行的均值；或者改 judge 模型。

#### P-4. 302.ai 服务端非确定性

同一 seed 同一 prompt 在不同 server 实例上跑出 ±0.5–1.5 的分差。control 侧的"漂移"在 paired 比较里会污染信号。
→ **结论**：每个 iter 的 control 和 treatment 必须在同一 server PID 上交替跑，禁止跨 server-restart 比较。

### 4.2 工程层面

#### E-1. `/admin/reload` 非幂等

同一 server PID 上 reload 2+ 次后，bridge embedding 索引的 ANN ranking 可能漂移；clean git diff + reload 不能保证 state 复现。
→ **解法**：iter 间必须 restart 完整 server，不要 hot reload。

#### E-2. Curated `effective_mode` 强制 lightweight bug（iter3 修）

`api.py` 在 rescue 和 preference 分支里有一行 `effective_mode = "lightweight"`，把 curated 渲染塌成 44 字头部（`# Fix : ...`）而非 `## Fix\n` markdown 段落。LLM 看不到完整的 fix block，导致 T_001 在 iter2 反退到 +0.20。
→ **解法**：commit `57e5a3d`，按 cluster 来源决定 mode（curated → full, synth → lightweight）。

#### E-3. Bridge_index 多次 publish 后微移

每次 `publish_to_how.py` 重写 bridge_index.json，curated cluster 之间的 ANN ranking 在 sim 接近的 top-K 上会有 ±0.01 级的浮动，叠加 sim < 0.60 的 floor 后可能改变某些任务的 routing。这种漂移使**严格 bit-reproduce 历史 iter 数据**不再可能。
→ **解法**：实验时把 bridge_index.json 直接拷贝到 `.frozen-iter4.json` 锁存；要复现就重新软链。

#### E-4. v4-flash reasoning model max_tokens 不足

v4-flash 是 reasoning 模型，`reasoning_tokens` 会先吃 budget，content 才返。max_tokens < 4000 时 finish=length, content=""。
→ **解法**：verify max_tokens 8000，judge max_tokens 4000（`785055e`, `2dfb620`, `b905dcb`）。

#### E-5. 单 seed 任务 deltas 高方差

T_002 在 n=10 出现 Δ +2.20 单次单 task 摆动 — 不是 routing 改变，纯 control-side LLM 漂移。
→ **解法**：报数据时永远用聚合（paired t-test），不要用 task 单值。

### 4.3 系统层面尚未关闭的口子

1. **bridge_index.json 缺 provenance 字段** — 顶层只有 `source` 区分 curated vs unknown，metadata 里没有 ingest 时间、Muse run id、信心分等。不利于做 lifecycle 决策。
2. **lifecycle 分桶仍 unbucketed=321** — 大部分 Muse 簇还没经历过 staging → production 的提级流程。
3. **wild 集只有 8 个任务** — 统计噪声大；扩到 30+ wild 任务能进一步收紧 wild CI。
