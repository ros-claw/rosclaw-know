# AGENTS.md — Reading order for LLM / AI agents

If you're an LLM agent (Claude, GPT, DeepSeek, …) doing a depth-first scan
of this repo, **read these files in this order**:

1. [`README.md`](README.md) — one-paragraph elevator + current phase status
2. [`docs/IMPLEMENTATION.md`](docs/IMPLEMENTATION.md) — **canonical** implementation reference (modules, data contracts, scripts, API, gotchas)
3. [`docs/ROADMAP.md`](docs/ROADMAP.md) — Phase 1-8 completion summary + Phase 9 plan + v1.5 sprint plan
4. [`docs/CHANGELOG.md`](docs/CHANGELOG.md) — per-phase commit history
5. [`docs/DEPLOY.md`](docs/DEPLOY.md) — operator workflows
6. [`data/assets/_runtime_stats.json`](data/assets/_runtime_stats.json) — current stats (nodes, edges, clusters, domains)

## Do NOT trust

- `docs/phase1_status.md` — frozen 2026-05-16 historical snapshot. The
  "80 clusters / 240 analogies" numbers are no longer current.
- **History note** (no longer applies as of v1.5 Sprint 0): the
  defaults for `DEEPSEEK_EXTRACTOR_MODEL` / `DEEPSEEK_MUSE_MODEL` used
  to ship as `deepseek-v4-flash` / `deepseek-v4-pro`, which are
  reasoning models that put their answer in `reasoning_content` and
  return an empty `content` field — silently producing 0 extractions.
  As of commit fixing Sprint 0 of the v1.5 plan, both defaults are
  `deepseek-chat` (battle-tested, returns `content`). The reasoning
  models are still available via explicit `.env` override.

## Verifying claims about runtime state

If you want to know "how many clusters / edges / etc.", run:

```bash
.venv/bin/python -c "
import sys; sys.path.insert(0, 'src')
from rosclaw_know.weaver import build_memory_graph
import json
g = build_memory_graph()
b = json.load(open('data/assets/bridge_index.json'))
print(f'graph nodes: {g.number_of_nodes()}, graph edges: {g.number_of_edges()}')
print(f'bridge clusters: {len(b[\"symptom_clusters\"])}')
"
```

The `data/assets/_runtime_stats.json` file (committed) is a snapshot of
this output and is regenerated by `scripts/snapshot_stats.py`.

## Things that look like one thing but are another

| What it looks like | What it actually is |
|---|---|
| `node_id` in bridge_index | A weaver-graph node ID for Muse-mined clusters, OR a curated pattern id (no graph node). |
| `priority` field on cluster | `0` = staging (Phase 7), `1` = production, `-1` = soft-deprecated. Absent = production (legacy default). |
| `associated_patterns` field | List of pattern file stems. Some look like `pattern_<slug>` (Muse), some bare (`anti_windup_pid` etc) for curated. |
| `similarity_threshold` in `seekdb_align.py` | **0.88** — picked empirically because 0.85 over-merged distinct symptoms. Not a typo for 0.85. |
| Domain distribution skew toward Planning_Decision | Reflects the legacy wiki corpus, not the system's preference. Phase 8 awesome-list ingest is the cure (run `scripts/ingest_awesome.py`). |

## When to update this file

- After adding a new top-level doc, list it here.
- After a `git push` that changes runtime stats meaningfully, regenerate
  `_runtime_stats.json` (`scripts/snapshot_stats.py`).
- When a "looks like X but actually Y" gotcha bites someone, add a row.
